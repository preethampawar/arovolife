# B13 — F108: before/after digests on every admin, KYC and settings mutation

Client decision Q16: **YES — one sweep.** CLAUDE.md: "any admin action, any KYC
change, any settings change → `audit_log` entry with before/after hashes".
Staging: 19 of 3,235 rows carried a `before_hash`.

`row_hash`/`prev_hash` were already automatic (`AuditLog::booted()` links every
new row); the 1,126-of-3,235 figure is pre-chain history, not a live hole. So
this batch is about `before_hash` / `after_hash` only.

## Shared helper

`app/app/Modules/Compliance/Support/AuditDigests.php` — the single helper every
site now uses.

- `AuditDigests::of(Model|array|string|null $state): ?string` — raw 32 bytes via
  `AuditLog::digest()`, never hex. `null` in → `null` out, so a create stores
  `before_hash` NULL rather than the digest of nothing.
- `AuditDigests::snapshot(Model $model, array $only = []): array` — the model's
  attributes, `$only`-pinned where an action governs named fields.
- Canonical: keys sorted recursively, every scalar normalised to its string form
  (a model just written holds ints and Carbons where the same row read back
  holds strings — without this an untouched column would move the digest),
  `updated_at` dropped.
- PII: identity-number attributes (`pan*`, `aadhaar*`, `account_number`,
  `bank_account`) digest in their masked last-4 form, exactly as B10's
  self-service bank audit; credentials and `*_enc` ciphertext collapse to `set`.
  A digest must not become a lookup oracle over a PAN-sized space.
