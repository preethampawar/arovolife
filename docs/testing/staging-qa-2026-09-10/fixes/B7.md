## F113 — fixed (commit `4ba08399`)

`NoIncomeProjection` was a lowercase `str_contains` over 23 fixed phrases, so
"You can earn ₹50,000 per month guaranteed with arovolife." walked through it
(the amount splits `earn per month`; the word order splits `guaranteed income`).

**Files**

- `app/app/Modules/Shared/Rules/NoIncomeProjection.php` — added `BANNED_PATTERNS`
  (8 regexes), `REVIEWED_EXCEPTIONS` (the published no-guarantee disclaimer) and
  a `normalise()` step that strips markup / decodes entities / collapses spaces
  before both the phrase list and the patterns run. The phrase list is unchanged,
  so `PublicCopyAuditTest` (which reads `BANNED_PHRASES`) is untouched.
- `app/tests/Modules/Shared/NoIncomeProjectionTest.php` — new. 1 test for the exact
  T35 sentence, 12 rewordings that must be refused, 8 legitimate sentences that must pass.

**The shapes now refused**: earning word + amount + period (`earn ₹50,000 per
month`, `Rs 2,000/day`, `₹1,00,000 monthly`); earning verb + period with no
amount; guarantee word + money noun; `fixed` directly on a money noun; amount +
`guaranteed|assured|promised` in either order; percentage + return noun;
`guaranteed|assured|fixed|up to` + percentage. No pattern crosses `.!?\n`.

**Why an amount + period alone is not refused.** That is how the plan states a
*cap* — "up to ₹10,000 a month" (repurchase), "capped at ₹1,00,000/month" (ADC),
"₹50,00,000 per Distributor per month" (plan ceiling) — and DSA §6.2 requires the
caps to be published. An earning word has to sit in front of the amount.

**False-positive sweep** (script over `database/seeders/content/*.md`, all
`PublicCopyAuditTest` Blade roots, `database/seeders`, `resources/help`): 5 line
hits, none new and none on a surface this rule validates —
`ethics.md` "passive income" and `step9-consent.blade.php` "assured income" are
pre-existing phrase-list hits on copy the rule exempts (untyped policy pages) or
the audit test already reviews; `resources/help/compensation.md` ×2 are internal
staff docs the rule never sees. Seeding passes.

**Tests**: `NoIncomeProjectionTest` (21 assertions) + `Announcement|ContentPages|
FaqLibrary|PublicCopyAudit|PublishContentPage|PublicContentPages` (43 passed).

**Follow-up (not done, out of scope)**: `PublicCopyAuditTest` still scans Blade
with the phrase list only. Extending it to `firstBannedPhrase()` would fail the
build on the four legitimate cap sentences above unless they are reworded or
listed as reviewed exceptions — a decision, not a mechanical change.

## F17 — fixed (commit `06db9187`)

`ContentPageSeeder::run()` published all five policy pages, so `db:seed` and
`platform:reset` both published the un-notified Wednesday–Tuesday payout week
(R-75, DSA §6.2).

**Files**

- `app/database/seeders/ContentPageSeeder.php` — `run()` now publishes the four
  and calls a new `seedAsDraft()` for `HELD_SLUGS = ['compensation']`, which
  **creates the page as a draft only where it is absent** and leaves an existing
  row untouched. It also warns with the command that publishes it.
- `app/tests/Pest.php` — `seedConsentDocuments()` now calls a new
  `publishHeldContentPages()`; registration consents to the compensation page
  (`ConsentDocuments::PAGES['plan']`), so tests do what a deploy does.
- `app/tests/Modules/Content/ContentPagesTest.php` — new CP-009 asserts the page
  is `draft` / `published_at = null` after seeding; the two CP-008 tests publish
  it by name first.
- `docs/runbooks/fresh-install-and-reset.md` — new step 9
  (`content:publish compensation`) with why it is separate, plus a note on the
  reset's seeder list.

**Why "create only if absent" rather than force-draft.** Demoting a page an
environment has legitimately published after serving the §6.2 notice would take
a statutory disclosure offline *and* break registration — `ConsentDocuments`
refuses to record a consent when the page is not published. Not rewriting an
existing row is also the exact control R-75 asks for (the un-notified body is
never pushed).

**Operational consequence to flag**: on a *fresh* environment (or after a reset
that wipes `content_pages`) registration refuses until
`php artisan content:publish compensation` is run. That is deliberate and
documented in the runbook, and the failure is loud ("the 'compensation' content
page is not published"), but it is a new deploy step. On staging/production the
page is already published, so nothing changes there.

**Tests**: `ContentPages|PublishContentPage|PublicContentPages|Consent` (34),
`tests/Modules/Identity` + `tests/Modules/Consent` (189), `PlatformResetTest`.

## F26 — fixed (commit `05a46013`)

**Files**

- `app/database/seeders/RolesAndPermissionsSeeder.php` — new `content.publish` in
  `SHARED` → `admin-operations`, `admin-compliance` (plus `admin` + `developer`
  by the loop). Still strictly additive (`firstOrCreate` + `givePermissionTo`);
  `admin-finance` does not hold it.
- `app/routes/web.php` — `can:content.publish` on all six `/admin/content` and all
  six `/admin/announcements` routes; `recompute-all` and `reset-purchase-data`
  moved from `can:finance.record` to `role:developer`.
- `app/tests/Feature/Compliance/SeparationOfDutiesTest.php` — SOD-11
  (admin-finance 403 on content index, announcements index and announcement
  store; operations and compliance not 403) and SOD-12 (no admin-family role can
  POST either recompute endpoint).
- `app/phpstan-baseline.neon` — one count bump (17 → 25) for the pre-existing
  `actingAs` ignore on that test file; it was already drifted (20 at HEAD).
- `app/resources/help/admin-actions.md` — role table rows updated.

**Deviation from the spec, deliberate**: `recompute-progress` did **not** get
`role:developer`. B1's F84 test asserts that endpoint returns **404** for every
admin-family role, from the controller check; a `role:developer` middleware
returns 403, which tells a reader a role they do not hold exists. The controller
check (B1) already closes it, so the poller keeps the 404 and both destructive
POSTs carry the role gate. Noted in the route comment.

**Deploy note (carries over from T35 finding #7)**: `content.publish` is a new
permission row — `RolesAndPermissionsSeeder` must be re-run on every environment
or operations/compliance will 403 on the content and announcement screens while
`admin`/`developer` pass through the `Gate::before` bypass. Same class of miss as
`messaging.moderate`, which is still absent on staging.

**Tests**: `SeparationOfDuties` (12) + `AdminEngineRunsController` (39) = 51
passed; `AdminHelp|Content|Announcement|Faq|Admin` sweep 527 passed.
