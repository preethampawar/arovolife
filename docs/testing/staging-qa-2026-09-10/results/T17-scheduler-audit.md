## Defects

1. **[Medium] Compensation queue worker timeout drifts from ADR-0011.** `/etc/supervisor/conf.d/ahdhesuhty_3.conf` sets `--timeout=999` where ADR-0011 (`docs/architecture/adr-0011-queue-transport-database.md`) explicitly mandates **7200**. `RecomputeAllJob` (`$timeout=7200`) and `RunEngineChainJob` (`$timeout=3600`) are unaffected because Laravel's per-job `$timeout` property overrides the worker's `--timeout` CLI flag (`Worker::timeoutForJob`, verified in `vendor/laravel/framework/src/Illuminate/Queue/Worker.php:351-353`). `PropagateGroupBvJob` and `ReverseGroupBvJob` (both `onQueue('compensation')`) declare no `$timeout` of their own and would silently get capped at 999s, not 7200s, if they or a future compensation job ever needed longer. Expected: supervisor conf timeout = 7200 per the accepted ADR. Actual: 999. Fix: correct the Cloudways Supervisor Job 3 panel setting (per ADR-0011's own admission that "Two panel defaults silently break a new job... documented in §1.9" — this one slipped through), or add explicit `$timeout` properties to every `compensation`-queue job so the conf value is never load-bearing.

2. **[Medium] `PropagateGroupBvJob` / `ReverseGroupBvJob` set `$tries = 3`, silently overriding the compensation queue's documented `tries=1` policy.** ADR-0011 §5 is explicit: "Job 3 runs each job once (tries 1) for visibility, not for safety... A visible failure in `failed_jobs`... re-triggered by a person once the cause is known, is the intended recovery." Laravel's `Job::maxTries()` / `Worker::markJobAsFailedIfWillExceedMaxAttempts` (verified in `vendor/laravel/framework/src/Illuminate/Queue/Worker.php:679,707`) gives the job's own `$tries` property priority over the worker's `--tries=1` CLI flag, exactly as it does for timeout. Both jobs declare `public int $tries = 3;` with no comment acknowledging the ADR. Likely **not** a double-crediting risk — `GroupBvAccumulatorService` uses a unique-constraint-based upsert (confirmed by comments at lines ~121, ~158 referencing "unique-constraint violation... fall back to an increment update"), consistent with ADR-0011's own idempotency argument — but it does defeat the stated visibility intent: a transient failure on either job gets two silent retries (60s backoff) before it ever shows up in `failed_jobs`/Pulse/Engine Runs, contrary to the documented "fail visibly the first time" policy. This is adjacent to but distinct from the already-tracked R-61 (missing `WithoutOverlapping`, concerned with concurrent workers via `retry_after`, not sequential retries via `$tries`). Not previously recorded anywhere in `docs/compliance/risk-register.md`. Recommend either changing both to `$tries = 1` to match policy, or amending ADR-0011/R-61 to document the intentional exception and why it's safe.

3. **[Low] Cannot independently verify the cron entry for `ahdhesuhty` exists** — `crontab -l` as `master_mvgumpkwtu` shows one line, for a different app (`dssjtmjcpv`) on the same server; `/var/spool/cron/crontabs/` is unreadable without root. Strong behavioural evidence (weeks of on-the-minute `engine_runs`, live per-minute log heartbeat) says the scheduler is in fact firing, so this is not scored as a failure, but it is a genuine audit blind spot for whoever only has this SSH credential — flag for the orchestrator to get Cloudways panel or root access if a definitive answer is ever needed (e.g. before a launch sign-off).

4. **[Low, informational] Scheduling inconsistency, not a bug today.** The 12 entries in `routes/console.php` use `withoutOverlapping()->runInBackground()` but never `onOneServer()`; the 3 entries registered by `ComplianceServiceProvider`/`PublicServiceProvider`/`MessagingServiceProvider` use `onOneServer()->withoutOverlapping()` but never `runInBackground()`. Inert on staging's single-app-server topology; would matter the day a second app server is added for this app. Also `adc:purge-rejected-documents` and `payments:redact-events` are both scheduled at the identical `03:15` daily slot — different unrelated tables, no evidence of contention, purely cosmetic.
